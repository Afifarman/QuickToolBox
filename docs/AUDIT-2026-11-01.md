## Verified findings

### F-01 — Canonical URL environment configuration is ignored (fixed in this branch)
- Evidence: `lib/site-config.js` defines `resolvedSiteUrl` from the documented environment-variable order, but exports `SITE_URL` using `normalizeSiteUrl(CANONICAL_SITE_URL) || resolvedSiteUrl`.
- Since the hard-coded canonical URL is valid, environment-provided `NEXT_PUBLIC_SITE_URL` and Vercel URL values never win.
- Impact: future domain changes and preview/deployment URL behavior can silently use the old hard-coded hostname, contrary to the file's documented contract.
- Fix: use `resolvedSiteUrl` first and retain the current canonical hostname only as fallback.

### F-02 — In-memory rate-limit storage is unbounded and instance-local (partially hardened in this branch)
- Evidence: `lib/security/rate-limit.js` stores every client key in a module-level `Map`, with no expiry sweep or size ceiling.
- Impact: arbitrary distinct client keys can grow the map for the lifetime of a warm process. In serverless deployments, each instance also has its own map, so the configured limits are not a globally consistent per-user/IP quota.
- Fix in this branch: periodically prune expired keys, cap the map at 10,000 entries, and fail closed when full.
- Remaining limitation: this is still process-local, best-effort throttling. A shared durable rate-limit store (e.g. managed Redis/Upstash) is required for reliable cross-instance enforcement; no external store credentials or service were configured/changed.

### F-03 — AI Photo Editor request-size error text is inconsistent (fixed in this branch)
- Evidence: `app/ai-photo-editor/page.js` accepts at most 3 MB; `app/api/ai/photo-edit/route.js` also enforces `MAX_IMAGE_BYTES = 3 * 1024 * 1024`, but its 413 response says 8 MB.
- Impact: users receive incorrect upload guidance when the API rejects a file.
- Fix: align the API error text with the actual 3 MB limit.

### F-04 — AI Photo Editor is Gemini-only
- Evidence: `app/api/ai/photo-edit/route.js` reads Gemini API key variables and calls Gemini image-generation models only. The text AI route has separate Groq/OpenRouter/Hugging Face fallback logic, but that does not provide image-editing fallback.
- Impact: configured text-AI providers do not make Photo Editor available if Gemini image-model access or quota is unavailable.
- Recommendation: show Gemini-only requirements clearly and add a genuinely compatible image provider only after its API, free-tier limits, image input/output, and licensing are verified. Do not silently substitute text output for an edited image.

### F-05 — AI provider availability endpoint reports key configuration, not provider health
- Evidence: `GET /api/ai` returns `available` based on whether environment keys exist and explicitly says it does not perform live health checks.
- Impact: clients must not interpret `available: true` as proof that a model is reachable, permitted, or has quota.
- Recommendation: label this state as “configured”; use a separate bounded health probe if live status is needed.

### F-06 — CI currently builds but does not run a test or lint suite
- Evidence: `package.json` defines only `dev`, `build`, and `start`; `.github/workflows/ci.yml` runs `npm ci` and `npm run build`. Security workflow separately runs `npm audit --audit-level=high` and build.
- Impact: route behavior, calculators, PDF operations, auth flows, and accessibility regressions are not covered by automated tests in these workflows.
- Recommendation: add focused unit/API tests and lint/static checks before treating a green build as full functional verification.

### F-07 — Supabase browser client pins a project URL in source
- Evidence: `lib/supabase/client.js` sets `EXPECTED_SUPABASE_URL` to a fixed project and substitutes it whenever the public environment URL differs.
- Impact: changing the Supabase project via Vercel environment variables alone will not switch the browser client; code and provider configuration must be migrated together.
- Recommendation: document this intentional pin or replace it with validated environment configuration in a separately tested auth change. Do not change provider settings in this audit.
